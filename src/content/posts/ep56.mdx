### 📕 Shownotes

一个 Next.js 网站让人觉得慢，有时并不是接口或打包的问题，而是点了链接之后页面没有任何反馈。这一期就从这种「跳转没有状态」的体验说起：没有加载提示时，网站会显得很慢，哪怕后台其实已经在工作。节目用 Next.js 的 useLinkStatus 来补上这段空白，改善加载状态和点击之后的响应，并拆开看这个小小的 API 能把体验抬起多少。

标题里的「急急急」对应的就是那种点下去却不知道有没有点中的焦急。文字说明没有展开成一份迁移手册，而是把问题收在导航反馈上：用户需要看见「正在前往下一页」。useLinkStatus 被当成完成这件事的那个接口。分类是 nextjs、fe 和 programming，主播是 AnnatarHe，适合已经在用 Next.js、又觉得站内跳转发闷的人。

官方文档链接就在下面，参数和返回值以 Next.js 文档和节目里的演示为准。这一集是第三季的第 56 期，发布于 2026 年 3 月 8 日，主播是 AnnatarHe。节目页上的小宇宙、YouTube 和 Bilibili 是三个收听和观看的入口。如果你的 Next.js 站点一点链接就好像卡住，可以先从「有没有把跳转状态做出来」查起，再决定要不要继续查接口和打包。

### 本期要点

- Next.js 页面跳转如果没有反馈，网站会显得很慢
- 用 useLinkStatus 补上加载状态，改善交互响应
- 讨论集中在一个小 API 带来的体验差别，而不是整站重构
- 分类：nextjs、fe、programming
- 文档入口：Next.js 的 useLinkStatus
