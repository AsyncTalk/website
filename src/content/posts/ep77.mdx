### 📕 Shownotes

很多人觉得 Skills 火了之后 MCP 就凉了。但 MCP 0728 这次更新，我愿意叫它「MCP 2」。

**MCP 1 的老毛病：有状态**

远程连接要一直维持 session，扩缩容和负载均衡都很难做。一发新版本，用户聊着聊着就断了，只能重开 session。

**Skills + CLI 真的完美吗？**

- CLI 靠单词拼接，表达力不如自然语言
- 必须有机器来跑（本地或云端 VM），成本高
- CLI 是黑盒，npm 那种供应链攻击蔓延到 Skills 只是早晚的事
- 一个命令是读还是写，全靠开发者自觉遵守语义

**MCP 0728 改了什么**

它去掉了 session，变成像 HTTP 一样的无状态接口，每次请求带上 header 就行：

- 扩容和 load balance 又能按熟悉的方式做了
- 每个 tool 都分只读和写，权限好管，也方便审计
- 跑在远程 server 上，不碰你的电脑，更安全

**实战演示**

我用 ShellTime 和 Rawback 的 MCP server 演示：只读 tool 一键「Always allow」，写和删除单独授权；再让 Claude 直接分析我最近的 AI 使用数据。

有自己产品的朋友，真心建议自己实现一个 MCP server 试试。你觉得 MCP 0728 能 make MCP great again 吗？你站 MCP 还是 Skills？欢迎在评论区聊聊。
